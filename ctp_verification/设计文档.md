# CTP 程序化交易客户端接入验证 — 设计文档

> 适用环境：飞泰穿透式验证（截图工具 Genesis.exe + 本客户端）
> 任务清单：`ctp_verification/task_config.yaml`（编号 0–32，共 33 项）
> 实现位置：`ctp_verification/`（独立模块，不耦合其他模块，不改 vnpy 核心）

## 一、背景与硬性要求

以本 vnpy 仓库为基础框架，完成飞泰要求的全部 33 项验证任务，逐项实操、用飞泰专用截图工具（Genesis.exe，读取本目录 task_config.yaml）截图提交审核。

已确认的硬性要求：

1. **所有功能点必须实现且界面可视化、可截图**（仅写日志不算完成）。
2. **真实交易逻辑**：下单/撤单/改单必须让 CTP 服务端收到真实请求，界面与回报逻辑、时间一致；统计计数只来源于真实发出的请求与柜台回报。
3. **两套网关都要可用**：vnpy_ctptest（CTP 6.7.2 评测环境 6666@61.186.254.137）与 vnpy_ctp（6.7.11）。两者 CTP DLL 不兼容、不能同进程，分别由 `examples/veighna_trader/run_ctptest.py` 与 `run.py` 启动。
4. 2.9 暂停交易采用「25 暂停策略执行」方案（监控面板暂停开关 + CTA 全部停止）。
5. 已同意对 vnpy_ctptest 网关做最小就地补丁（纯字段映射/日志，零逻辑改动，`patches/` 留底）。

## 四、引擎设计（engine.py）

### 4.1 下单/撤单包装

- 引擎初始化时以**实例属性替换** `MainEngine.send_order/cancel_order`（幂等标记 `_ctr_wrapped`，close 时还原，threading.Lock 保护计数）——手动交易、CTA 策略、脚本全部经此路径，通过的请求**真实透传网关**。
- `pre_check` 拒绝项（本地拒绝=不发柜台，弹窗+错误页记录+WARNING 日志，符合 2.7"终端系统检查出错误并拒绝报单"）：
  1. 暂停交易已开启；
  2. 合约不存在（合约列表非空时；合约未加载完成时放行并提示一次）；
  3. 限价/FAK/FOK 价格非 pricetick 整数倍（`Decimal` 精确比较）或限价单价格 ≤ 0；
  4. 数量 < min_volume、非最小单位整数倍、> max_volume（优先柜台真值，None/0 时按合约覆盖值或默认兜底值）。
- 网关返回非空 vt_orderid 才计**报单笔数**（真实送达柜台）；返回空记【发送失败】日志。

### 4.2 重复检测

- 报单指纹 = (vt_symbol, direction, offset, price, volume)，可配窗口（默认 5 秒）；
- 模式 `warn`：第二笔**放行但提示**（两笔均真实入柜台，委托界面同参数两笔即重复报单铁证）；
- 模式 `block`：第二笔本地拦截；
- 撤单重复 = 窗口内对同一 vt_orderid 重复发撤单指令。

### 4.3 统计与阈值

- 撤单笔数 = 本端真实发出的撤单请求（维护 `cancel_requested` 集合，排除 IOC 自动撤销等干扰）；
- 撤单成功数 = 仅统计本端请求过撤单的 CANCELLED 回报（每单一次）；
- 分钟桶趋势（保留最近 240 分钟），每分钟写一条【统计】日志；
- 阈值 latch 回滞：`prev < threshold <= now` 触发一次，回落后解除可再触发；
- 预警 = 弹窗（可关）+ 蜂鸣（可关）+ 卡片红色高亮 + 【预警】WARNING 日志；
- 统计每 60 秒落盘 `.vntrader/ctr_stats_YYYYMMDD.json`，同日重启恢复（防评测中断丢证据）。

### 4.4 事件处理（EventEngine 线程）

- **EVENT_ORDER**：更新委托明细（状态用柜台回报原文）；REJECTED → 柜台拒单计数；CANCELLED∈本端请求 → 撤单成功计数；重连回放的旧单入明细但不计报单数。
- **EVENT_LOG**（只匹配网关固定中文串，两网关一致；MainEngine 日志会被 gettext 翻译成英文，绝不解析）：
  - 连接状态机：`连接成功`→连接中（黄）；`合约信息查询成功`→交易通道就绪（绿）；`行情服务器登录成功`→行情通道就绪；`连接断开，原因N`→断开（红）+断开告警预警；
  - 柜台错误路径一（write_error）：正则 `，代码：(\d+)，信息：(.+)$` → 柜台错误表（与 ±3 秒内同网关拒单委托自动关联，错误码写入明细备注，附常见错误码提示）；
  - 柜台错误路径二（委托状态更新，交易所拒绝主路径——非交易时段/涨跌停板/状态禁止等）：正则 `^委托 (\S+) 状态更新，(\d+):(.+)$`（错误码在 StatusMsg 的 `NN:` 前缀）→ 柜台错误表（委托号直连回写明细备注）+ 计入柜台拒单数（重连回放的旧委托只入表留证、不计入）；
  - 每条柜台错误同时输出一条【柜台错误】WARNING 日志（网关原生 write_error 为 INFO 级，补 WARNING 保证任务 2.11-32 按级别可检索）；
  - **回放去重**：路径二按（委托号, 错误码）会话内终身去重；路径一日志行不含委托号，按（网关, 码, 信息）300 秒窗口去重——重连时柜台会重复推送当日错误回报。
- 报单/撤单成功各输出一条【委托】/【撤单】中文 INFO 日志（任务 2.11-29 交易日志检索依据；MainEngine 原生下单日志为英文）。
- **EVENT_TIMER**：过期指纹清理、分钟桶裁剪、统计快照（每秒推送驱动界面）。

### 4.5 界面动作入口

`set_trading_paused`（只拦报单不拦撤单，含改单重报部分）、`reset_stats`、`update_setting`（写 `.vntrader/ctr_setting.json`）、`batch_cancel`（逐笔真实撤单）、`modify_order`（改单=真实撤原单+真实重报，reference="CtrModifyOrder"）、`stop_all_strategies`（调用 CTA 引擎全部停止）。

## 五、界面设计（ui/widget.py）

单窗口（功能菜单「程序化交易监控」），顶部状态条 + 五标签页：

```text
状态条：[CTPTEST 交易:●就绪 行情:●就绪（富文本着色）] [⏸暂停交易(红色checkable)]
        [重置统计] [停止全部CTA策略]
Tab1 监控总览：6 计数卡片（报单/撤单/撤单成功/重复报单/本地拒绝/柜台拒单，超阈值变红）
              + pyqtgraph 分钟柱状图（报单/撤单/重复三系列，最近60分钟）
              + 委托明细表（时间/委托号/代码/方向/开平/价/量/状态/来源/备注）
              + 连接状态历史表
Tab2 阈值与预警：报单/撤单/重复报单阈值、重复窗口、重复模式、默认兜底手数、
              按合约手数覆盖、弹窗/声音开关 + [保存并生效]
Tab3 批量撤单：活动委托勾选表（2秒自动刷新）+ [全选已报][全选部分成交][全不选]
              [批量撤单]→警示确认弹窗（含笔数构成）→分批执行（每批10笔、间隔1秒防流控）
              [改单]→改单对话框（预填原值）→撤原单+真实重报
Tab4 错误信息：柜台错误表（时间/接口/错误码/柜台信息/常见提示/关联委托号）
              + 本地拒绝记录表（时间/检查项/拒绝原因/委托内容/来源）
Tab5 日志中心：日期下拉（扫描 log/vt_*.log）+ 级别筛选 + 关键词 + [检索]
              + 结果表（最多显示5000条）+ [导出txt][导出csv]
```

- 表格复用核心 `BaseMonitor`（右键导出 CSV、排序、信号桥），自定义事件作 event_type；
- 跨线程安全：引擎回调在 EventEngine 线程，全部经 `QtCore.Signal`（自动 QueuedConnection）桥接到 Qt 主线程；弹窗/蜂鸣只在主线程执行。

**vnpy_ctptest**（`site-packages/vnpy_ctptest/gateway/ctptest_gateway.py`）：

## 八、关键风险与对策

- 网关中文日志文案是解析依据（两网关一致）；绝不解析 MainEngine 日志（本环境 gettext 翻译成英文）——统计只在包装函数内做。
- 引擎在 EventEngine 线程，弹窗/声音必须经 Qt 信号跨线程；计数器加锁。
- 浮点价位/数量比较一律 `Decimal`；阈值 latch 防重复弹窗。
- warn 模式重复报单两笔都真实进交易所——演示后立即撤余单；批量撤单分批防流控。
- 重连后统计不清零（任务 6 要求计数连续性）；旧单回放入明细不计报单数。
- **共享测试账号洪水防护**（2026-11-12 实测：评测账号多测试方共用，他人疯狂报撤单时柜台把数万条错误回报推给所有连接，约 400 条/秒，2 分钟写 5 万行日志拖死 GUI）：网关补丁 3 按错误码节流（每码每 60 秒最多 10 行 + 1 行汇总）；引擎侧再加速率闸（10 秒内最多登记 20 条，超出只压制计数、每分钟汇总一条 WARNING）+ 错误表上限 2000 条。两层节流保证正式验证演示期间 UI 不被他人刷死。
- `ruff check .` 全仓覆盖（本包须保持整洁）；mypy/pytest 仅覆盖 vnpy/ 与 tests/（离线测试 `tests/test_ctp_monitor.py` 用假网关验证引擎全链路）。
